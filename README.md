# 女仆军团（Maid Legion）

一个 **Minecraft 1.20 / 1.20.1 Forge** 的《车万女仆》（Touhou Little Maid）伴生模组。

按一个键呼出全屏面板，像指挥一支小队一样指挥你的女仆：战斗中**一键召唤**，战斗结束后**一键收回**。

> **本模组的定位是「战斗指挥」，不是「仓库管理」。**
> 目标是在战斗的几秒内完成编队调度，而不是离线整理女仆数据。

## 支持版本

| | 版本 |
| --- | --- |
| **Minecraft** | **1.20 和 1.20.1**（同一个 jar 通用） |
| Forge | 47.x（1.20 / 1.20.1 用的就是这一系） |
| 车万女仆 | 1.5.0+（Forge 版） |

> 1.20 与 1.20.1 之间原版 API 差异极小，车万女仆自己也是**一个 jar 同时覆盖这两个版本**
> （它的声明同样是 `[1.20,1.20.2)`），所以本模组采用相同的做法。

> 本模组**不包含任何 TLM 的代码或美术素材**，仅通过其公开 API 交互。TLM 代码部分为 MIT，
> 素材部分为 CC BY-NC-SA 4.0，本项目只调用代码 API，因此不受素材条款约束。

## 招募：用御币把女仆编入军团

**面板只管你主动招募的女仆**，不会自动接管你所有的女仆。这是刻意的设计——面板能跨维度传送、
还能消耗材料复活，如果自动包含全部女仆，一次误点就可能把不想动的女仆拉走。

| 操作 | 效果 |
| --- | --- |
| 手持御币（`hakurei_gohei` **或** `sanae_gohei`），`Shift + 右键`女仆 | 加入军团 |
| 对已加入的女仆再做一次 | 移出军团 |
| 驯服一只新女仆 | **自动加入**（驯服本身已是很明确的操作） |

> 两种御币都行。它们在 TLM 里是同一个类（`ItemHakureiGohei`），所以本模组用类型判断，
> 任何继承该类的附属模组御币也能直接用。

> ⚠️ 注意：**御币不是用来驯服女仆的**。TLM 里驯服女仆用的是**蛋糕**（可配置）。
> 御币在 TLM 里的用途是**搭建祭坛**（对核心方块右键）。本模组只是复用了这个道具作为
> 「编入军团」的手势。

## 快捷键

| 默认键 | 功能 |
| --- | --- |
| **`.`**（句号） | 打开女仆军团 |
| **未绑定** | 一键召唤 / 收回 |

### 关于那个「召唤 / 收回」键

它**默认是空的**，请自己去「选项 → 控制」里设置一个顺手的键（比如 `V`、`R`、鼠标侧键）。

因为它只有一个键却要做两件事，所以**按下时自动判断方向**：

| 勾选女仆的状态 | 按键效果 |
| --- | --- |
| 有「**已收起**」的 | **放出**她们（从数据还原到身边） |
| 全都在世界里 | **收回**她们（收成数据） |
| 都在身边、没什么可做 | 提示「已在身边，无需操作」 |

> 实际用起来就是：战斗中按一下把人拉过来，战后按一下把她们收起来，不需要切模式。

### ⚠️ 只对「勾选的」女仆生效

这个键**只作用于你在终端里勾选的女仆**：

| 勾选情况 | 按键效果 |
| --- | --- |
| 勾了若干 | 只操作这些 |
| **一个都没勾** | **什么都不做**，屏幕提示「请先勾选女仆」 |

这是刻意的设计：避免你只想叫 2 个女仆，结果手一抖把全家都拉过来。

**勾选状态会保留**——关掉面板、甚至打死怪再开，勾选都还在。所以战斗中你先勾一次，之后就能一直盲按快捷键。用 `Ctrl+A` 全选、或者面板右上角的「全选 / 反选 / 清空」来快速改选。

## 收藏（星标）与置顶

每行**最左边有个星标**，点一下即可收藏。收藏的女仆**永远排在最上面**——凌驾于状态、时间、名字之上。

| 操作 | 效果 |
| --- | --- |
| 点击星标 | 收藏 / 取消收藏 |
| 点「★ 只看收藏」 | 只显示收藏的女仆（再点一次恢复显示全部） |

星标显示为 `*`（金色）表示已收藏，`-`（暗色）表示未收藏。

收藏状态**按玩家保存**，重进世界、重启服务器都还在。

> 典型用法：把你最常带出门的几只星标起来，平时点「只看收藏」，列表就只剩这几只，
> 战斗中勾选和召唤都不会误伤到别的女仆。

## 列表是怎么排序的

排序结果**完全确定**（刷新多少次顺序都一样）：

1. **收藏优先**：星标的女仆永远在最上面（含未加载、已收起的）
2. **再按状态**：`在列` → `已收起` → `未加载`
3. **同状态内**：最近收起的排前面 → 再按名字（忽略大小写）→ 最后按 UUID

最后一步按 UUID 是必要的：**女仆可以重名**（比如两只都叫「雾雨魔理沙」）。少了这一步，
同名女仆的顺序会在每次刷新时变动，你刚勾选的那一行可能下次就跑到别处了。

为了让你能区分重名女仆，已收起的行会显示**收起时间**和**短 ID**：

```
雾雨魔理沙   已收起 3m 前 · #a1b2
雾雨魔理沙   已收起 2h 前 · #7f3c
```

## 四种状态的含义

理解这四个状态是用好本模组的关键：

| 状态 | 含义 | 能召唤吗 | 能收回吗 | 能复活吗 |
| --- | --- | --- | --- | --- |
| **在列** | 女仆实体已经加载，就在世界里 | ✅ 直接传送 | ✅ | ❌ |
| **已收起** | 女仆已被收成存档数据，实体不存在 | ✅ 从数据直接放出 | ❌（本来就是收起态） | ❌ |
| **未加载** | 女仆在 TLM 的世界记录里，但她的区块没加载（走远了，或**在别的维度**） | ⚠️ **取决于该女仆的强加载开关** | ❌ | ❌ |
| **阵亡** | 女仆死亡，已被本模组托管（**没有墓碑**） | ❌ | ❌ | ✅ **见下** |

## 阵亡与复活（不掉落、不爆一地）

### 女仆阵亡时会发生什么

对**已编入军团**的女仆，死亡时本模组会**接管**，而不是走 TLM 原本的墓碑流程：

| | TLM 原生 | 本模组（军团内女仆） |
| --- | --- | --- |
| 掉落物 | 进墓碑，**打开墓碑东西爆一地** | **完全不掉落**，全部保留在女仆数据里 |
| 墓碑 | 生成 | **不生成** |
| 恢复方式 | 捡墓碑 → 去祭坛复活 | **面板里点一下** |

> **她的装备不会丢**：护甲、主副手、女仆背包、饰品、隐藏栏、任务栏、经验——
> 这些本来就在女仆的存档数据里，所以复活后**原样回来**，不需要你重新穿装备。

> **Curios 饰品也保得住**：它们不在女仆自己的存档数据里（而在 Curios 的能力中），所以本模组
> 在**死亡瞬间**单独取出并清空，复活时**放回原来那一格**。装没装 Curios 都能正常工作。

> ⚠️ **你自己没编入军团的女仆不受影响**，仍按 TLM 原生方式生成墓碑。

### 复活方式

**把鼠标移到那只女仆的「阵亡」状态徽章上**，徽章会变绿并变成「复活」，点一下即可。

| 需要 | 数量 |
| --- | --- |
| 青金石、金锭、红石、铁锭、煤炭 | **各 1** |

材料清单与 TLM 祭坛的复活配方（`reborn_maid.json`）**完全一致**，所以面板不会比祭坛更便宜。

> 注：祭坛配方还需要 0.5 的祭坛 power（来自祭坛多方块结构），面板无法读取该数值，
> 因此改为收取物品，避免绕开祭坛的能量成本。

复活是**立即生效**的：材料一扣，女仆当场出现在你身边、满血、装备原样。

### 神龛读条复活（1.3.0 已实现）

在全军强化页用 **3 个神龛**一次性解锁「**神龛复活**」，之后它是一个开关：

- **开启**：点「复活」走**读条**路线，**不消耗任何材料，也不再扣神龛**
- **关闭**：回到上面的材料立即复活

**代价只有等待**，而且读条时长随她**短时间内的阵亡次数**变长：

| 情况 | 读条 |
| --- | --- |
| 孤立的一次阵亡 | **3 秒** |
| 短时间内反复阵亡 | 每多 1 点「热度」**+3 秒** |
| 上限 | **30 秒** |
| 降温 | 每 **10 分钟**自动 −1 点热度 |

读条期间主人掉线**不会取消**——解锁已经付过，半途作废没有道理，会挂起等他回来。

> ⚠️ 这条路线**不需要别的东西**：解锁费就是那 3 个神龛，之后每次复活是免费的。

### 好感度惩罚

TLM 里女仆死亡会 **-2 好感度**（好感度决定她的攻击力和生命上限）。本模组**保留**这个惩罚。

> 🐞 **1.1.1 及更早版本其实是「一点都没扣」——这是个 bug，1.2.0 修好了。**
>
> 我们的死亡快照取自 `LivingDeathEvent` 的 `HIGHEST` 优先级，而 TLM 扣好感度的监听器
> （`event/maid/MaidDeathFavorability` → `Type.DEATH`）用的是**默认优先级 `NORMAL`**，
> 也就是**我们的快照比扣分更早**。复活时把快照读回去，等于把 TLM 刚扣掉的分又还了回来。
>
> 现在复活时会**按 TLM 自己的 `Type.DEATH` 数值把惩罚补扣回去**（数值是读出来的，不是写死 2，
> TLM 改了我们也跟着变）。想彻底免掉这个惩罚，就去买全军能力里的**「阵亡好感度全免」**。

## 强化面板（1.2.0）

在终端里勾选**恰好一只**女仆，点底部的「强化」。面板有两个标签页，定位完全不同：

| 标签页 | 货币 | 定位 | 内容 |
| --- | --- | --- | --- |
| **单体强化** | **这只女仆自己的经验** | **数值成长** | 9 项，每项 **100 级** |
| **全军强化** | **你的 P 点仓库** | **特殊能力** | 3 项，**1 级买断**，对已招募的全部女仆永久生效 |

> 为什么全军页不卖数值？因为那样它就只是「单体强化的批量版」，两个界面没有区别。
> 所以 P 点买的一律是**规则层面**的东西：更快长经验、免掉死亡惩罚、跟着你飞。

### 单体强化（9 项 × 100 级，花她自己的经验）

| 升级 | 每级 | **满级总加成** |
| --- | --- | --- |
| 攻击力 | +0.05 | **+5.0 攻击** |
| 生命上限 | +0.4 | **+40 生命** |
| 护甲 | +0.1 | **+10 护甲** |
| 伤害强化 | +1% | **+100%** |
| 远程攻速 | +1% | **+100%** |
| 移动速度 | +0.5% | **+50%** |
| 拾取范围 | +0.05 | **+5 格** |
| 饥饿上限 | +0.2 | **+20** |
| 幸运 | +0.2 | **+20** |

> **每级为什么这么小？** 因为要走 100 级。如果攻击按 +1/级，满级就是 **+100 攻击**，
> 而她的基础攻击只有 2——那是彻底崩坏。所以每级给很小的数，界面显示的是**累计总值**
> （"1.85 攻击"），进度靠进度条看。

**成本分段**（同级同价，跳档很好记）：

| 等级区间 | 战斗类每级 | 功能类每级 |
| --- | --- | --- |
| 1–20 | 20 | 10 |
| 21–40 | 120 | 70 |
| 41–60 | 600 | 400 |
| 61–80 | 2,500 | 1,500 |
| 81–100 | 6,000 | 4,000 |

- **满级一项**：战斗类约 **18.5 万**经验，功能类约 **12 万**。
- **九项全满**约 **140 万**经验——这是终局工程，不该能速通。

**经验的来源**：她捡到的经验球，以及她捡到的 P 点（每点折算 1/4 经验，这是 TLM 的原规则）。

> ⚠️ **「未加载」的女仆不能强化。** 她的 NBT 存在 TLM 自己的世界数据里，我们读写不到。
> 先把她的**强加载**打开并召唤一次，再强化。

### 全军能力（3 项，花 P 点仓库）

| 能力 | 效果 | 价格 |
| --- | --- | --- |
| **全军经验加成** | 所有已招募女仆获得的经验 **+100%** | 80 P |
| **阵亡好感度全免** | 阵亡**不再扣好感度**（原生 −2） | 100 P |
| **飞行跟随** | 你**创造飞行**时，女仆跟着你飞，不用在地上跑 | 120 P |

三项合计 **300 P**，也就是仓库的默认上限。

### P 点仓库（为什么必须另建）

TLM 的 P 点上限**改不了**：`PowerCapability.MAX_POWER` 是 `static final`，而且
`add()` / `set()` 里的 `5.0f` 是**编译期内联的常量**（已用字节码确认）。不魔改 TLM 就没有任何
办法把钱包撑到 5.0 以上。

所以本模组另建了一个仓库（默认上限 **300**），做法是：

| 操作 | 行为 |
| --- | --- |
| **自动转入**（默认开） | 钱包超过 **1.0** 的部分，**每秒**自动进仓库 |
| 存入全部 | 手动把钱包清进仓库 |
| 取出全部 | 从仓库取回，最多取到钱包上限 5.0 |

> **自动转入为什么是每秒轮询？** 因为 TLM **没有**玩家捡 P 点的事件——`playerTouch` 直接调
> 能力接口，溢出转普通经验也是写死的。只有持续把钱包抽空，才能**始终留出拾取空间**，
> 这才是真正「提高存储量」的手段。

> ⚠️ **代价**：钱包会长期接近 0（默认只留 1.0）。如果你要用 TLM 的祭坛（需要 0.5 power），
> 先点「取出全部」。不想要这个行为就关掉自动转入，或把配置里的阈值调到 5.0（等于关闭）。

## 「强加载」开关（重要）

### 为什么需要它

TLM 自己有一个机制：**区块卸载前**，如果女仆是同维度、且没开「家模式」、且能移动，
就会把她**传送回主人身边**。

但它的判定里有硬性的一条：**要求主人和女仆在同一维度**。所以：

- 你**走路走远** → 女仆会被自动带回你身边 ✅
- 你**地图传送 / 下界传送门 / 跨维度指令** → 女仆**留在原维度**，变成「未加载」状态 ❌

这正是需要「强加载」的场景。

### 开关做什么

| 开关 | 行为 |
| --- | --- |
| **开** | 该女仆所在区块**持续保持加载**（即使你走远、甚至去了别的维度），因此随时可被一键召唤 |
| **关**（默认） | 保持 TLM 原生行为，本模组完全不介入 |

开着的时候她会一直待在那儿活动、干活，代价是**该区块会持续占用服务器资源**——所以别给太多女仆开。

### 实现方式（为什么是安全的）

用的是 Forge 的 `ForgeChunkManager.forceChunk`，**不是**原版的 `setChunkForced`：

| | `setChunkForced`（不用） | `ForgeChunkManager`（在用） |
| --- | --- | --- |
| 存储 | 写进存档 `forcedchunks.dat` | 运行时票据，不写存档 |
| 归属 | 无归属，谁都清不掉 | **按女仆 UUID + 模组 ID** 记账 |
| 女仆死亡/删除 | 区块**永久残留在加载** | 票据随实体自动失效，**不会泄漏** |
| 关闭开关 | 无效 | 立即释放 |

另外还有一层保险：**每 20 tick 重新确认一次**，女仆走到新区块会自动改跟；服务器重启后会按开关状态**自动重新加载**，不会因为重启就失效。

### 跨维度召唤

顺带说明：如果你在**别的维度**，跨维度召唤走的是「存 NBT → 目标维度重建」这条路，**不需要加载区块**。
因为 TLM 的女仆记录表是整个存档唯一一份（存在主世界），跨维度查询天然可用。

### 首次开启的提示

第一次给某个女仆打开强加载时，会弹一个说明窗口，讲清楚它会临时加载区块、可能增加服务器负担，
建议只给常用的女仆开启。确认后不再重复提示。

**本模组不设数量上限**——由你自己权衡。

服主可以在配置文件里把 `allowForceLoad` 设为 `false`，彻底禁用所有区块加载行为
（此时开关会显示但不可点击）。

## 配置

`config/touhou_maid_legion-common.toml`

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `maxSummonPerAction` | `12` | 单次操作最多处理多少只女仆 |

## 从源码构建

需要 **JDK 17**。

```bash
# Windows
gradlew.bat build

# 开发调试（会启动带 TLM 的客户端）
gradlew.bat runClient
```

产物：`build/libs/touhou_maid_legion-1.2.2-forge+mc1.20.1.jar`

文件名格式为 `<模组id>-<版本>-<加载器>+mc<MC版本>`，与车万女仆官方的
`touhoulittlemaid-1.5.3-forge+mc1.20.1.jar` 保持一致的风格。

> 本模组是 **Forge 专用**的（用到了 Forge 的 `SimpleChannel`、`ForgeChunkManager`、
> `@Mod` 等 API，这些在 Fabric 上不存在），所以文件名里的 `forge` 是准确的。
> 若日后移植到别的加载器，把 `gradle.properties` 里的 `mod_loader` 改掉即可，
> 文件名会自动跟着变。

### ⚠️ 构建前必须先放入 TLM 的 jar

TLM **没有**发布到任何公开 Maven 仓库，本项目用 `flatDir` 从 `libs/` 读取它。
**这个 jar 不在本仓库里**（它属于 TLM 作者，23 MB，不应被转载），所以克隆后需要自己放一份：

1. 从 [CurseForge](https://www.curseforge.com/minecraft/mc-mods/touhou-little-maid) 或
   [Modrinth](https://modrinth.com/mod/touhou-little-maid) 下载 **TLM 1.20.1 Forge** 版
2. **原样**放进 `libs/`，文件名不要改。`flatDir` 是按 `名字-版本.jar` 查找的，
   带额外的前缀会导致找不到

即：

```
libs/touhoulittlemaid-1.5.3-forge+mc1.20.1.jar
```

> ⚠️ 注意：`gradle.properties` 里坐标写的是 `tlm:touhoulittlemaid:...`，但 `flatDir`
> **会忽略 group 部分**，实际只按文件名 `touhoulittlemaid-<版本>.jar` 查找。
> 所以文件名必须是 `touhoulittlemaid-` 开头，写成 `tlm-touhoulittlemaid-...` 会构建失败。

换 TLM 版本时，改文件名并同步修改 `build.gradle` 里的 `compileOnly` / `runtimeOnly` 坐标。

这个 jar **不会**被打包进产物（用的是 `compileOnly` + `runtimeOnly`）。

## 已知限制

- 只管理**自己的**女仆（`isOwnedBy` 校验），不能操作他人的。
- 女仆**死亡留下的墓碑**不在此面板管理，请用 TLM 自己的方式处理。
- 跨维度召唤会让女仆**离开她原本的工作点**。如果你希望她长期驻守某地，请不要对她开启强加载，
  或召唤后用 TLM 的原生方式重新安排她的家/工作点。
- 若 TLM 未来大改内部 API，本模组会在启动时自检并**降级为「只显示在线女仆」**，而不是崩溃。
- **女仆是放在地面上召唤的**：如果你**飞在空中**，周围没有落脚点，召唤会被拒绝并提示你先落地。
  这是有意为之——把她放进半空里，她只会摔下来。
